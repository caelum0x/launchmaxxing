### 1. Catalog expanded 24 -> 82 directories (`catalog.py`)

- Added 58 new entries across six category families called out in
  `STRATEGY-2026-10-23.md` section 1 as the single biggest competitive gap vs. SubmitMap
  (366), OpenLaunch (239), SubmitFleet (339): AI-tool/GEO directories, browser-extension
  stores, API marketplaces, newsletter sponsor slots, Slack/Discord community lists,
  vertical-SaaS/integration-ecosystem directories, plus four more Reddit communities.
- Every one of the 58 new submit URLs was live-verified with real `curl` requests during
  this session (not guessed) -- confirmed-working paths were kept as-is; Cloudflare/bot-
  blocked-but-real sites (same pattern the original 24 already used for G2/Capterra/
  AlternativeTo) got an honest note instead of a fabricated "it works" claim; dead/
  unreachable guesses (ProgrammableWeb, several blind AI-directory-name guesses, several
  wrong submit paths) were dropped entirely rather than included unverified.
- `catalog.py` gained `export_csv`/`export_json`/`export_opml` + `CSV_FIELDS`.
- README/pyproject.toml's "24" claims updated to 82 (the only places making a factual
  claim about catalog size; CHANGELOG's historical entries were left untouched as a
  historical record).

### 2. `dashboard.py` + `dashboard`/`serve` commands

- New module: inline-CSS/inline-SVG self-contained HTML dashboard (progress rings for
  directories/checklist, a submission timeline built from the raw SQLite event history,
  outreach/content/UTM summary cards). Zero external asset, zero network request, opens
  via `file://` or a real server.
- `launchmaxxing dashboard <product>` writes it to `~/.launchmaxxing/dashboards/<slug>.html`
  (or `--out`); `launchmaxxing serve <product>` runs a localhost-only `http.server` that
  re-renders on every GET so the open tab always reflects live state.
- `report --html` reuses the exact same template; `report --json` emits the full `track`
  payload. (Backlog items 2 and 11 share this implementation.)

### 3. `dogfood.py` + `dogfood` command

- Runs `content`'s generators against launchmaxxing's own real product profile
  (hardcoded `LAUNCHMAXXING_PROFILE`, not a placeholder) for the six directories
  STRATEGY's growth move #2 names (PeerPush, Turbo0, Smol Launch, StartupBase,
  Microlaunch, Findly Tools) that are not yet self-submitted, writing one Markdown
  evidence file per directory into `launch-evidence/` and saving a content draft to the
  local DB.
- Deliberately never auto-submits or auto-creates an account (all six require a free
  account to finish a listing, per their catalog notes) -- `--mark-submitted` only
  records the tracker status after a human confirms they actually did the real
  submission. Ran for real against this repo's own state: 6 evidence files generated
  into `launch-evidence/` (gitignored, same as this project's existing manual-submission
  screenshots for other products).

### 4. `init --interactive` onboarding wizard

- `state.py` gained `set_default_profile`/`get_default_profile` (stored per-product).
- `init --interactive` prompts step-by-step for tagline/problem/audience/differentiator/
  url/pricing/subreddit (gracefully errors on closed stdin instead of hanging), saves the
  answers, then falls through to the normal `init` plan output.
- `_build_profile` (shared by `content`/`outreach draft`) now layers saved-default <
  `--profile-file` < explicit flags, so neither command needs any profile flag re-supplied
  once a product has been initialized interactively. Verified end-to-end via piped stdin.

### 5. `outreach send` -- SMTP sending, drafted-and-tracked

- `outreach.py` gained `send_email`/`smtp_configured`/`OutreachSendError`, reading
  `LAUNCHMAXXING_SMTP_HOST/PORT/USER/PASSWORD/FROM/USE_SSL` -- the user's own mail
  provider, zero third-party account, zero cost beyond what they already pay their mail
  host. Dependency-injectable `smtp_client` for testing (same pattern as the existing
  `transport` abstraction).
- `db.py`: `outreach_contacts` gained `email`/`sent_at`/`send_status`/`send_error`
  columns, auto-migrated onto an already-existing database file via `ALTER TABLE` (no
  manual DB migration step for anyone upgrading).
- `outreach send <contact_id>` drafts the channel-appropriate message, sends it, records
  `sent`/`failed` + the error, and auto-advances a `not_contacted` contact to `contacted`
  on success. Verified: `send_email` tested against an injected fake SMTP client
  (host/port/STARTTLS/login/message assembly all correct); CLI error paths (SMTP not
  configured, contact not found, no email on file) verified against the real command.

### 9. `watch.py` + `watch` command

- Background-poll loop re-running `linkcheck.check_all` + `track`'s stale-directory/
  stale-outreach detection on an interval, diffing against the previous cycle so only
  *newly*-appeared problems notify (never re-spams the same already-known issue every
  cycle), firing a native macOS notification via `osascript` (falls back to a stdout log
  line, never crashes, on any other OS). Verified: real `osascript` notification fired;
  diff/dedup logic unit-verified with synthetic broken-link/stale-contact snapshots
  (first-ever poll never notifies; repeat identical state never re-notifies; a genuinely
  new issue does notify, exactly once).

### 10. `backlinks.py` -- multi-competitor mode

  listed on a directory we know about" check) or unions the category fallback when not
  live, into one deduped "submit here too" list with CSV export. Verified against a
