## 1. CLI surface (every subcommand, exact contract)

Entry: `launchmaxxing <command> [args]` (`src/launchmaxxing/cli.py:build_parser`).
Global flags on every subcommand (`_add_common`): `--state-file PATH`
(else `LAUNCHMAXXING_STATE` env, else `~/.launchmaxxing/state.json`),
`--db-file PATH` (else `LAUNCHMAXXING_DB` env, else
`~/.launchmaxxing/launchmaxxing.db`), `--json` (machine-readable).
`launchmaxxing --version` prints `__version__` (must stay synced with
`pyproject.toml`'s `version` — regression-tested in `test_cli.py`).

## 2. Data model (all local, no server)

`~/.launchmaxxing/state.json` (`state.py`, one JSON blob, `json.dumps(...,
sort_keys=True)`):
```
{"products": {"<name>": {"platforms": {"<platform_id>": {status, note,
  submitted_at, updated_at}}, "steps": {"<step_key>": {status, note,
  updated_at}}, "created_at}}, "pain_point_drafts": [{id, product_name,
  query, subreddit, thread_url, thread_title, snippet, upvotes, age_days,
  draft_reply, status, created_at}]}
```

`~/.launchmaxxing/launchmaxxing.db` (`db.py`, SQLite, 4 tables, each
`id TEXT PRIMARY KEY` = `uuid4().hex`):
- `submission_events(product_name, platform_id, status, note, created_at)` — append-only.
- `outreach_contacts(product_name, name, channel, handle, status, note, created_at, updated_at)`.
- `content_drafts(product_name, platform, kind, body, created_at)`.
- `utm_links(product_name, platform_id, base_url, source, medium, campaign, content, full_url, created_at)`.

Both stores are independent; `track.build` is the only place that joins
them for a single product.

`backlinks.py` now reuses both (see §0).

## 4. What remains to build (ranked)

1. **Catalog breadth vs. competitors.** OpenLaunch (239 platforms) /
   SubmitFleet (339) dwarf our 24. Any new entry needs: real submit URL,
   live-verified `account_free` (plain HTTP GET + read the form, not just
   the homepage), category tags, `verified_at`. Do this in small batches
   (5-10 at a time) with `--check-links` re-run after each batch — do not
   bulk-import an unverified list, 5 of 24 already needed correction after
   initial add.
2. **`report --format json`.** `report.render_markdown` only emits
   Markdown; `track.build`'s dict is already JSON-serializable via
   `--json` on `track` itself, so `report`'s only gap is the `--out` file
   path not having a JSON sibling. Low effort, add if a consumer (e.g. a
   future status-page generator) needs it — no current caller needs it,
   do not build speculatively.
3. **`backlinks --allow-live` end-to-end verification.** CrawlGraph/
   DataForSEO paths are unit-tested against a fake transport only; no
   owner credential exists to exercise either live path for real. Owner
   blocker: sign up for CrawlGraph's free tier (15 calls/month, no card —
   not a spend, but still an owner account-creation step) if this is ever
   worth doing.
4. **PyPI publish.** Owner blocker per `RELEASE.md`: PyPI account + 2FA +
   API token/trusted publisher. No code change possible from this side;
   `pip install git+https://github.com/caelum0x/launchmaxxing.git@v0.2.5`
   is the only install path until then.
5. **Lint nits (non-blocking).** `ruff check src tests` → 2 pre-existing
   findings, neither touched this session: `catalog.py`'s `__all__` not
   isort-sorted (cosmetic), `linkcheck.py:48` blind `except Exception`
   (intentional — catches any transport failure mode uniformly, matches
   `reddit_search.py`'s same pattern; leave as-is, do not add noqa).
