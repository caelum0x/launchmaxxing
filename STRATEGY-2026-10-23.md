# launchmaxxing -- competitive strategy, ICP, journey, growth moves (2026-10-23)

Scope note: this doc covers competitive positioning and user research only.
Feature/page/API planning for this product is tracked separately in
`PLAN-2026-10-23-DEEP.md` if/when that file exists (not present as of this
writing) -- do not duplicate that content here.

Current product snapshot (from README.md / pyproject.toml / CHANGELOG.md,
version 0.2.4, 2026-10-23): a free, MIT-licensed, local-only Python CLI.
24 catalogued launch directories (link-checked live), submission history in
local SQLite, a 10-step checklist, local template-based launch-copy
generation (no LLM call), an outreach pipeline, a UTM link builder,
read-only Reddit pain-point search with draft replies, competitor backlink
lookup, and a shareable Markdown report. No account, no server, nothing
auto-posts. Not yet on PyPI -- `pip install` only works via a pinned GitHub
tag or local clone (confirmed blocker, see RELEASE.md; owner-only: PyPI
account + 2FA).

## 1. Direct competitors

- **SubmitMap** (submitmap.com) -- cloud SaaS, freemium. Free tier: browse
  366 directories, no account. Paid tier (monthly/yearly, exact price not
  publicly listed by the vendor; third-party trackers report ~$33/mo in
  verified Stripe revenue) unlocks a submission dashboard and an MCP-based
  AI agent that fills forms in the user's own browser.
  - Strongest feature: per-platform disqualifier data (which free tiers
    closed, which platforms reject which product types) before you submit,
    plus 366-platform breadth.
  - Weakest point: tracking and automation are both behind a paid cloud
    account -- no local/offline option, and pricing itself is opaque
    (reviewers note "pricing not provided publicly").

- **OpenLaunch** (github.com/Securiteru/openlaunch) -- free, MIT, open
  source. 239 platforms (66 with detailed field-level data). Agent-native:
  you clone the repo and point an AI coding agent (Claude, Cursor, Devin)
  with browser automation at a product-brief template; a static local
  tracker shows status.
  - Strongest feature: largest *open* platform registry with real
    reconnaissance data, and an explicit agent-contract (AGENTS.md) gating
    account access/payment/public actions.
  - Weakest point: requires the user to already have an AI coding agent
    with browser-automation capability and burn its API credits per
    submission -- there is no standalone CLI path, no outreach tracking,
    no content generation, and no historical analytics.

- **SubmitFleet** (github.com/profullstack/submitfleet) -- free, MIT, open
  source, self-hosted. 339 directories catalogued (203 free). Ships CLI,
  TUI, HTTP API, MCP server, and a web dashboard; durable workers, AES-256
  credential sealing, spend caps.
  - Strongest feature: the most production-grade architecture of any
    competitor (atomic intents, leasing/fencing against duplicate
    submissions, audit trail) -- clearly built for teams/repeat campaigns.
  - Weakest point: **0 of 339 destinations have a working submission
    adapter** as of the current repo state (only TinyLaunch is
    contract-tested, not live) -- the core promise (automated submission)
    does not work yet, and setup requires Node/pnpm plus a database
    (local SQLite or Turso/libsql).

- **"Done for you" manual submission services** -- LaunchDirectories ($99,
  3-6 day manual delivery, 30-100+ directories), StartupSubmit ($99
  Starter/$199 Growth/$299 Authority, 60-200+ directories with DR
  guarantees), SubmitSaaS ($60/$100/$140 one-time, hybrid automation +
  human review), SubmitStorm ($99-$499 scaling with directory count,
  ~$0.66-$1.43/directory), ListingSaaS ($99 flat, ~$0.99/directory).
  - Strongest feature collectively: someone else does the manual form-
    filling labor and hands back screenshot proof -- genuinely saves ~20
    hours for a non-technical founder.
  - Weakest point collectively: one-time paid service, not a tool you keep
    -- no ongoing checklist/outreach/content/UTM tracking, you pay again
    per product, and none of them generate your launch copy or track your
    outreach contacts.

- **LaunchList checklists / PHLaunchChecklist.com / TheLaunchChecklist.com**
  -- free-to-$79-$299 static checklists (Notion/Airtable/Google Sheets or
  a webpage), no software, no tracking automation, no database.
  - Strongest feature: zero setup, works for a non-technical founder with
    no terminal.
  - Weakest point: static content only -- no submission history, no link
    verification, no content generation, nothing is actually tracked once
    you close the tab.

## 2. Exact differentiation plan (one concrete axis per competitor)

- **vs. SubmitMap (price + no-account axis):** launchmaxxing's tracking
  and dashboard-equivalent (`track`, `report`) are free and local today;
  SubmitMap puts the same capability behind a paid account with no public
  price. Keep literally zero paywall on `track`/`submit --history`/
  `report` -- that gap (a login wall for dashboard features) is the
  single thing to keep advertising against SubmitMap by name in the
  README comparison section.

- **vs. OpenLaunch (workflow axis -- no AI-agent dependency):** OpenLaunch
  requires an AI coding agent with live browser automation and its own API
  spend just to read the playbooks productively. launchmaxxing's `init`,
  `content`, `outreach draft`, and `directories --check-links` all run as
  plain deterministic Python with zero LLM calls and zero extra cost.
  Concrete move: add one README line under Install -- "No AI agent, no API
  key, no browser automation required for any command" -- aimed directly
  at the subset of OpenLaunch's audience without a configured coding
  agent.

- **vs. SubmitFleet (feature axis -- working automation vs. 0/339
  adapters, plus setup speed):** SubmitFleet's own repo state shows 0 of
  339 directories have a working submit adapter yet; launchmaxxing doesn't
  promise auto-submission at all, but its `directories --check-links`
  already does real, working HTTP verification against all 24 live submit
  URLs today (proven: CHANGELOG 0.2.3/0.2.4 found and fixed two real stale
  URLs this way). Concrete move: keep `--check-links` as the headline
  "what we verify is what we ship" feature and never claim automated
  submission launchmaxxing doesn't do -- credibility differentiator against
  a competitor whose flagship feature is currently non-functional. Also:
  `pip install` + `launchmaxxing init` is one command and seconds; SubmitFleet
  requires Node/pnpm + database provisioning before first use -- call this
  out as "0 to first plan in under 5 minutes, no server to run."

- **vs. "done for you" $99-$299 services (price + retention axis):**
  launchmaxxing is $0 and reusable across every future product the same
  founder launches, while each paid service is a one-time per-product fee.
  Concrete move: add a one-line cost comparison to the README ("$0 vs.
  $99-$299 per launch, reusable for every product you ship after this
  one") placed right under the 24-directory catalog section, where a
  price-comparing visitor is already reading.

- **vs. static checklists (feature axis -- actual state, not a
  spreadsheet):** PHLaunchChecklist/TheLaunchChecklist are checked boxes
  in a doc with no verification and no history. launchmaxxing's `submit
  --history` keeps a timestamped status timeline per directory in SQLite,
  and `track --stale-days` actively flags directories/outreach that have
  gone cold -- a static checklist cannot do either. Concrete move: keep
  `track`'s staleness-reminder feature prominent in the README's first
  screenful; it's the one thing no checklist product can replicate without
  becoming software itself.

## 3. Primary user persona / ICP

- **Who:** a solo founder or 2-3 person founding team of a bootstrapped or
  pre-seed SaaS, dev tool, or AI product, comfortable in a terminal
  (already runs `git`/`pip`/`npm` daily -- this is not a no-code or
  non-technical founder).
- **Budget reality:** cannot or will not spend $99-$299 per launch on a
  manual submission service, and does not have a marketing hire or agency
  on retainer.
- **Job to be done:** get from "I have a working product" to "100 real
  users" within roughly 4-8 weeks post-launch, specifically by (a) not
  missing any of the free, account-free distribution channels that already
  exist for their category, (b) not re-typing the same launch copy five
  times for five platforms, (c) not losing track of which of the 20+
  outreach DMs/emails they sent actually got a reply, and (d) having proof
  (screenshots/links/history) that the work actually happened, not just a
  memory of having "done some launch stuff."
  secondary trigger: they are about to launch on Product Hunt / Show HN
  and are Googling "product hunt checklist" or "startup directories list"
  the week before launch -- the same intent captured by the competitors
  surfaced in section 1.

## 4. User journey map (discovery to retained user)

1. **Discovery** -- finds launchmaxxing via a GitHub awesome-list PR (e.g.
   `awesome-growth-hacking`, `awesome-cli-apps-in-a-csv`), a directory it's
   submitted itself to (Launching Next, PeerPush), the GitHub
   `directory-submission` topic page, or a Show HN / r/SideProject post.
2. **Evaluation** -- reads the README in under 2 minutes; the "no signup,
   no server, local state" framing and the 24-directory list with real
   submit URLs is the credibility check against competitors that gate
   features behind an account.
3. **Install** -- runs `pip install "git+https://github.com/caelum0x/launchmaxxing.git@v0.2.4"`
   (not yet `pip install launchmaxxing` -- PyPI publish is still an
   owner-only blocker per RELEASE.md).
   **-- FLAGGED: single biggest drop-off risk step.** A CLI-discovery
   user's default expectation is that `pip install <name>` just works;
   a pinned git+https URL with an explicit version tag is an extra
   copy-paste and an extra "is this safe/maintained" judgment call. Most
   competitors in section 1 (SubmitMap, the paid services) require zero
   install at all (browser-only), so this step is where launchmaxxing
   loses the most otherwise-qualified visitors relative to them.
4. **First run (`init "My Product"`)** -- the "value in under 5 minutes"
   moment: full directory list + 10-step playbook printed immediately,
   with no product data entered beyond a name. This is the moment that
   has to land, because it's the only thing standing between "pip install
   worked" and "I actually trust this enough to keep using it."
5. **Early retention actions** -- generates launch copy (`content`),
   records the first real submission (`submit ... submitted`), adds the
   first outreach contact (`outreach add`). Each of these requires
   supplying real product facts (tagline, problem, audience,
   differentiator) -- a second, smaller friction point, since it's the
   first moment the tool asks for more than a product name.
6. **Multi-week retained use** -- comes back repeatedly over the following
   2-6 weeks to update `submit` status, check `track --stale-days` for
   reminders, and pull `report` for a shareable summary. This is the
   loop competitors (one-time paid services, static checklists) cannot
   replicate, because they have no state to come back to.
7. **Paying/retained-user equivalent** -- since launchmaxxing itself is
   free, the closest equivalent conversion event is: (a) the user finishes
   a real launch using it end-to-end (checklist complete, directories
   live, report generated) and (b) the user becomes a referral source --
   stars the repo, mentions it in their own launch post, or submits it to
   a directory themselves. Track these two events as the actual "retained
   user" proxy metrics, since there is no payment step to measure instead.

## 5. Three concrete growth moves (follow from sections 1-4)

1. **Close the install-friction gap identified in step 3 of the journey
   map by finishing the PyPI publish, since that is a blocking owner step
   this session cannot complete (PyPI requires an account + 2FA per
   RELEASE.md) -- queue it explicitly as the single highest-leverage
   owner action, ahead of any further feature work, because it removes
   the journey map's flagged biggest drop-off step entirely. This is not
   generic advice; it is the fix for the exact friction point section 4
   measured.**

2. **Dogfood the tool's own content generator for its own launch copy and
   finish submitting to the account-free directories it ships but hasn't
   used yet.** `launchmaxxing` has used Launching Next (queue #165019),
   `github_awesome` (bekatom/awesome-growth-hacking#111,
   toolleeo/awesome-cli-apps-in-a-csv#536) per CHANGELOG 0.2.4, but has not
   yet self-submitted to the six newer 2026 account-free directories it
   added to its own catalog this cycle: PeerPush (GEO-optimized for
   ChatGPT/Claude/Perplexity discovery -- directly relevant since its ICP
   increasingly discovers tools via AI-assistant search, not just Google),
   Turbo0, Smol Launch, StartupBase, Microlaunch, and Findly Tools. Run
   `launchmaxxing content launchmaxxing show_hn` and `... product_hunt`
   against its own real product facts, record every submission with
   `launchmaxxing submit launchmaxxing <platform> submitted`, and keep the
   evidence in `launch-evidence/` the same way prior submissions were
   proven -- this is the exact workflow the tool sells, aimed at its own
   growth.

3. **Capture the comparison searches already happening around its real
   named competitors.** The web research for this doc surfaced that
   searchers actively compare "open source directory submission CLI"
   options (OpenLaunch, SubmitFleet) and "directory submission tool
   pricing" (SubmitMap, StartupSubmit, SubmitStorm) -- i.e. demand already
   exists for exactly this comparison. Add a short, factual comparison
   table to the README (no invented numbers -- use the real facts gathered
   in section 1/2: SubmitFleet's 0/339 working adapters, OpenLaunch's
   required AI-agent dependency, SubmitMap's paid/account-gated tracking,
   the $99-$299 one-time cost of manual services) and post it once as a
   genuine, specific reply (not a drive-by plug) in the GitHub
   `directory-submission` topic and in the r/SideProject thread(s) the
   tool's own `pain-points` search is already built to find -- placing the
   comparison exactly where people comparing these specific named tools are
   already looking, not generic SEO content.
